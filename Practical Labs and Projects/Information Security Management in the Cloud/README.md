\# Information Security Management in the Cloud



\## Overview



This section contains practical cloud security work completed as part of my Level 5 HND in Digital Technologies (Cybersecurity).



The module focused on information security management within cloud environments and the practical implementation of security controls using Amazon Web Services (AWS).



The work demonstrates the configuration, testing, and validation of identity and access controls, secure systems management, cloud storage permissions, resource policies, and controlled access to data.



\## Practical Implementation



The `AWS-Cloud-Security-Implementation` project contains sequential evidence of practical AWS security configuration and testing.



The implementation included:



\- Creating and managing IAM users and groups

\- Assigning different levels of access to AWS resources

\- Testing authorised and unauthorised EC2 actions

\- Validating access-denied security controls

\- Working with AWS Systems Manager

\- Reviewing managed instance inventory

\- Executing commands using Systems Manager Run Command

\- Accessing EC2 systems using Session Manager

\- Configuring Systems Manager Parameter Store

\- Testing application configuration changes

\- Creating and configuring Amazon S3 buckets

\- Uploading and managing S3 objects

\- Configuring S3 Object Ownership and ACL-related settings

\- Creating and modifying S3 bucket policies

\- Implementing explicit deny policies

\- Testing denied S3 upload operations

\- Configuring access to customer-record data

\- Testing direct object access restrictions

\- Configuring controlled public-read access

\- Creating S3 presigned URLs

\- Validating access to protected data

\## Testing \& Validation



Security controls were tested throughout the implementation to verify that permissions and restrictions behaved as intended.



This included confirming denied EC2 operations for restricted users, successful administrative operations for authorised users, S3 upload restrictions, direct object-access restrictions, controlled public access, presigned URL functionality, Systems Manager connectivity, and application configuration changes.



The evidence therefore demonstrates both the implementation of security controls and validation that those controls were functioning correctly.
